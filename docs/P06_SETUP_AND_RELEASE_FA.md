# راهنمای نگهداری، نصب و انتشار هما نیرو

## محدوده و وضعیت
- پروژه Django و PostgreSQL است. محیط فعلی توسعه روی Windows است و پایگاه فعال `homaniroo_dev` است؛ نام پایگاه مقصد هر عملیات باید مستقل تأیید شود.
- تنظیمات فعلی توسعه، از جمله DEBUG و اتصال دیتابیس با حساب دارای اختیار بسیار بالا، برای انتشار یا دسترسی شبکه‌ای مناسب نیستند. تا تکمیل بررسی امنیت، سامانه را در شبکه یا اینترنت منتشر نکنید.
- این سند مجوز تغییر تنظیمات، ایجاد حساب دیتابیس، نصب بسته، اجرای migration، ورود داده یا بازیابی پشتیبان نیست.

## آماده‌سازی یک محیط جدا
1. قبل از ساخت یا تغییر هر محیط، مقصد و نسخه سورس تأیید شود. محیط تست یا استقرار باید از پایگاه فعال جدا باشد.
2. در محیط جدا نسخه Python سازگار، PostgreSQL 17، محیط مجازی مستقل و بسته‌های دقیق `requirements.txt` بررسی شوند. نصب بسته‌ها اقدامی جداگانه و نیازمند تأیید است.
3. تنظیمات را با الگوی `.env.example` و مقادیر اختصاصی محیط فراهم کنید؛ رمز، کلید، فایل `.env`، داده مشتری و بکاپ هرگز در Git قرار نگیرند یا در گفتگو ارسال نشوند.
4. جداول `core` در بخش‌هایی از پروژه unmanaged هستند؛ صرف اجرای migrationهای Django به معنی ساخته‌شدن کامل ساختار عملیاتی نیست. ساختار، دسترسی‌ها و وابستگی‌های واقعی باید از پیش بررسی شوند. بدون طرح تأییدشده و پشتیبان معتبر، migration اجرا نکنید.
5. کنترل‌های بدون اجرای migration پس از تأیید مقصد: `python manage.py check`، `python manage.py makemigrations --check --dry-run` و `python manage.py migrate --check`. دستور آخر فقط وجود migration معوق را بررسی می‌کند.

## کاربران و داده‌ها
- فقط سوپرادمین فعال دسترسی سراسری دارد. مدیر هر شرکت اپراتورهای عادی همان شرکت را مدیریت می‌کند. تغییر وضعیت مشتری و خروجی گزارش برای مدیر شرکت یا سوپرادمین است.
- قبل از هر تغییر واقعی حساب یا داده: هویت و دسترسی، پیش‌نمایش دقیق، پشتیبان تازه و معتبر و امکان ممیزی بررسی و تأیید شوند. از ارسال رمز و هش خودداری کنید.
- ابزارهای یک‌بارمصرف مراحل قبلی ممکن است به یک نسخه تاریخی سورس وابسته باشند؛ صرف وجودشان مجوز اجرای دوباره یا حذف محافظ آن‌ها نیست.

## Git و GitHub
- Git برای سورس است، نه دیتابیس و اطلاعات مشتریان. نادیده‌گرفتن فایل جدید با `.gitignore` محتوایی را که قبلاً کامیت شده از تاریخچه حذف نمی‌کند. نام فایل نمونه `.env.example` مجاز است، به شرط نداشتن مقدار واقعی.
- تنظیمات فعلی `.gitignore` فایل‌های جدید CSV، SQL، اکسل، بکاپ، آرشیو و کلید را نیز نادیده می‌گیرد؛ فایل‌های قبلاً ردیابی‌شده خودکار حذف نمی‌شوند. برای نمونه یا اسکریپت بی‌خطرِ لازم، ابتدا محتوا را بررسی و سپس درباره افزودن صریح تصمیم بگیرید.
- پیش از اولین اتصال به GitHub: حساب با ورود دومرحله‌ای و مخزن خصوصی ایجاد شود؛ تاریخچه و محتوای قابل ارسال دوباره بررسی شوند. مخزن خصوصی هم تضمین محرمانگی کامل نیست. ساخت remote یا push فقط پس از تأیید جداگانه انجام می‌شود؛ رمز، token یا URL حاوی اعتبارنامه نباید در گفتگو یا مخزن ثبت شود.

## انتشار و بازگشت
- قبل از انتشار: محیط مجزا، HTTPS، تنظیمات production، سطح دسترسی محدود دیتابیس، لاگ بدون اسرار، کنترل دسترسی کاربران، به‌روزرسانی امنیتی وابستگی‌ها و آزمون‌های مناسب باید بررسی شوند. `runserver` سرور عملیاتی نیست.
- قبل از هر تغییر عملیاتی، نسخه سورس و برنامه بازگشت و پشتیبان تازه و امن مشخص شوند. بازگشت سورس لزوماً تغییرات دیتابیس را برنمی‌گرداند؛ برای سازگاری نسخه و داده باید برنامه جدا داشت.
- فهرست‌کردن آرشیو پشتیبان با `pg_restore --list` آزمون بازیابی کامل نیست. بازیابی آزمایشی فقط در محیط کاملاً جدا، با نام مقصد تأییدشده و مجوز صریح انجام می‌شود؛ هرگز روی پایگاه فعال.
