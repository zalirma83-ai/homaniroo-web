# اصلاح E04 — حذف نمایش کیفیت و نقص انتقال

## مرجع
- سورس مبنا: `634a770d48c9b973b29f94570fa517c3bdbb9d70`.
- سند نیازمندی: «کل ایرادها ۳ آبان»، بند E04 و تأیید ادامه کار در گفتگو.
- چهار اسکریپت قدیمی E04 عمداً توسط کاربر حذف شده‌اند؛ این اصلاح آن‌ها را بازنمی‌گرداند.

## دامنهٔ تغییر
- حذف فیلتر و ستون وضعیت اطلاعات در فعال‌ها، بالقوه‌ها و قراردادها.
- حذف فراخوانی اجزای کیفیت از صفحات پرونده مشتری، جزئیات و ردیف‌ها و مقادیر ماهانه قرارداد.
- حذف باکس تاریخ قراردادهای مهاجرت‌یافته و پنل کیفیت داشبورد؛ کارت هشدارهای عملیاتی باقی است.
- حذف شمارنده‌های تجمیعی کیفیت مرتبط در صفحه مشتری، قرارداد و گزارش مدیریتی؛ تاریخ‌ها و مقدارهای واقعی همچنان بدون حدس نمایش داده می‌شوند.
- حفظ تعداد ردیف انرژی قرارداد در سلول مشخصات قرارداد پس از حذف ستون کیفیت.
- لینک قدیمی با پارامتر quality دیگر در سه فهرست مذکور نتیجه را مخفیانه فیلتر نمی‌کند. صفحه‌بندی همان صفحات فقط quality را کنار می‌گذارد؛ سایر فیلترها محفوظ‌اند.
- ناشناخته بودن تاریخ یا نبود حجم در فهرست‌ها با ظاهر خنثی نمایش داده می‌شود؛ هشدار پایان نزدیک قرارداد و هشدارهای عملیاتی حفظ شده‌اند.
- چیدمان کارت‌ها و ستون‌های تغییرکرده با CSS محدود به همان صفحات اصلاح شده؛ تم، فونت و CSS اصلی تغییر نکرده‌اند.

## موارد عمداً بدون تغییر
- دیتابیس، migrationها، مقادیر کیفیت، سوابق، منبع داده و منطق ارزیابی پشت‌صحنه.
- ستون‌ها و دادهٔ تمام CSVها؛ حذف ستون CSV در این بسته انجام نمی‌شود.
- جدول و شاخص‌های کامل‌بودن انرژی؛ بند E08 جداگانه انجام خواهد شد.
- منطق خرید و فروش و تراز، واحدها، مالکیت، دوره خرید، وضعیت مشتری و مرز شرکت‌ها.
- پیام‌های خالی بودن بخش‌ها، مقادیر مفقود، اعتبارسنجی فرم، مجوزها و پیام‌های عملیاتی.
- اجزای تاریخی information_badges و information_details و توابع ارزیابی باقی‌اند، اما هیچ صفحه عملیاتی آن‌ها را فراخوانی نمی‌کند؛ وجود آن‌ها به معنی نمایش نیست.
- تنظیمات، اسرار، وابستگی‌ها، نصب بسته، Git staging/commit و انتشار.

## ایمنی نصب
نصب‌کننده باید در Downloads و خارج پروژه باشد. CMD در ریشه پروژه و محیط .venv فعال باشد. قبل از نصب، runserver و هر ابزار دیگری که فایل پروژه را می‌نویسد متوقف شود.
نصب‌کننده HEAD، هش تمام فایل‌های هدف، نبود تداخل برای فایل‌های جدید، فایل‌های محافظت‌شده و وضعیت Git را پیش از نوشتن بررسی می‌کند. فقط حذف ثبت‌نشده چهار اسکریپت قدیمی و فایل‌های ثبت‌نشده templates.zip و `'` از قبل مجازند؛ خود بسته هیچ‌کدام را تغییر نمی‌دهد.
پشتیبان خام و زمان‌دار فایل‌ها در Downloads/homaniroo_backups و خارج پروژه ساخته و کنترل می‌شود. پایان خط فایل موجود حفظ می‌شود. در خطای نصب، فایل‌های تغییرکرده برگردانده و فایل‌های جدید حذف می‌شوند؛ هر خطای بازیابی صریح گزارش خواهد شد. پس از نتیجه مبهم، بدون بررسی دوباره اجرا نشود.

## بررسی و پذیرش
- محیط محلی دستیار: Django 5.2.17، تست‌های SimpleTestCase و قالب‌ها با backend غیرفعال دیتابیس؛ هیچ اتصال یا آزمون روی PostgreSQL کاربر انجام نشده است.
- نتیجه محیط دستیار: ۱۴۶ تست بدون دیتابیس (شامل ۶۹ تست هدفمند مرتبط) و ۱۳ آزمون ایمنی نصب‌کننده موفق شدند؛ این نتیجه جای تست کامل PostgreSQL کاربر نیست.
- تست‌های جدید E04: نبود نمایش کیفیت، تعداد سلول و colspan، حفظ مقادیر مفقود، خنثی بودن تاریخ نامشخص، حفظ فیلترهای مجاز و هشدارهای عملیاتی، حذف اثر quality قدیمی، کامپایل قالب‌ها و جدا ماندن E08.
- انتظارهای قدیمی تست رابط متناسب با تصمیم جدید به‌روز شده‌اند؛ تست‌های منطق کیفیت و خروجی CSV حفظ شده‌اند.
- پس از INSTALL_OK، ابتدا `python manage.py check`، سپس تست هدفمند، سپس تست کامل روی محیط واقعی کاربر اجرا شود. تست ناموفق یا STOPPED یعنی توقف و بررسی؛ نه ادامه خودکار.
- بررسی دستی هر دو شرکت: داشبورد، فعال، بالقوه، راکد و پرونده، قرارداد/جزئیات، گزارش‌ها، صفحه خالی، صفحه‌بندی و فیلتر مالکیت/دوره خرید/جست‌وجو. نبود کیفیت در رابط، اثبات صحت تجاری اطلاعات نیست.
- در پایان git diff --check و git status؛ فقط مسیرهای همین اصلاح با git add -- ثبت شوند. فایل ناشناخته `'` و templates.zip وارد کامیت نشوند. هش واقعی پس از خروجی کامیت کاربر ثبت شود.

ساخت و آزمون بسته در محیط بررسی انجام شده؛ نصب روی ویندوز، تست کامل PostgreSQL و پذیرش دستی تا دریافت خروجی کاربر تأیید نشده‌اند.
